# Toss_Transaction_Recorder

## 1단계: 토스뱅크 거래내역 엑셀 → SQLite

현재 범위는 **엑셀 파일 1개를 SQLite로 가져오기 + 이미 저장된 거래 중복 등록 방지**입니다.
이메일 자동 수집, GMT Hub 연동, 거래내역 자동 삭제는 아직 구현하지 않습니다.

### 실행

Python 3.10 이상:

```powershell
python -m pip install -r requirements.txt
python import_excel.py "C:\\경로\\토스뱅크_거래내역.xlsx" --db "toss_transactions.db"
```

토스뱅크의 암호화된 원본 엑셀을 사용하면 프로그램 실행 시 암호를 입력받습니다.
**암호를 소스코드·GitHub·명령어에 기록하지 마세요.**

```text
[OK] 전체 323건 | 신규 323건 | 중복 제외 0건
[DB] .../toss_transactions.db
```

같은 엑셀을 재등록하면 새 거래를 추가하지 않습니다. 조회기간이 겹치는 다른 엑셀도 거래 단위로 중복 여부를 확인합니다.

### DB

- `transactions`: 거래 일시, 적요, 거래 유형, 거래 기관, 상대 계좌번호, 부호가 있는 거래 금액, 거래 후 잔액, 메모 및 중복 판별 키
- `import_runs`: 엑셀 파일별 가져오기 실행 기록 (전체/신규/중복 건수)
- 유니크 제약: `(source_account, fingerprint, occurrence_no)`

중복 판단은 동일 원본 계좌의 **거래일시·적요·유형·기관·상대 계좌번호·금액·거래 후 잔액·메모**를 바탕으로 합니다.
같은 파일 안에 모든 값이 똑같은 행이 여러 건이면 각 발생 횟수를 보존합니다.
원본 엑셀에 은행의 거래 고유번호가 없으므로 실제 거래의 모든 값이 동일한 경우에는 완벽한 식별이 불가능합니다.

잘못된 엑셀·거래 형식은 오류 처리하며 해당 파일의 데이터는 부분 저장하지 않습니다.

### 테스트

```powershell
python -m unittest discover -s tests -v
```

### 보안

은행 거래 원본(`.xlsx`)과 생성된 거래 DB(`.db`)는 Git 추적 대상에서 제외합니다.
**실제 거래내역 파일, 계좌정보, 암호는 공개 저장소에 커밋하지 마세요.**
SQLite DB 자체는 암호화되어 있지 않으므로 별도로 파일 접근 권한을 제한해야 합니다.
