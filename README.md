# Toss_Transaction_Recorder

## 1단계: 토스뱅크 거래내역 엑셀 → SQLite

현재 범위는 **엑셀 파일 1개를 SQLite로 가져오기 + 이미 저장된 거래 중복 등록 방지**입니다.
이메일 자동 수집, GMT Hub 연동, 거래내역 자동 삭제는 아직 구현하지 않습니다.

### 실행

Python 3.10 이상:

```powershell
python -m pip install -r requirements.txt
python import_excel.py "C:\\경로\\토스뱅크_거래내역.xlsx" --db "toss_transactions.db"
```

토스뱅크의 암호화된 엑셀은 프로젝트 폴더의 `.env`에서 암호를 자동으로 읽습니다.

1. `.env.example`을 복사해 프로젝트 루트에 `.env` 파일을 만듭니다.
2. `.env` 파일의 `TOSS_EXCEL_PASSWORD=` 뒤에 본인의 엑셀 암호를 기입합니다.
3. 평소처럼 `python import_excel.py "토스뱅크_거래내역.xlsx"`를 실행합니다.

`.env`에 암호가 없으면 기존처럼 실행 중 암호를 입력받습니다.
`.env`는 Git에서 제외되고, 저장소에는 값이 비어 있는 `.env.example`만 올라갑니다.
운영체제 환경변수 `TOSS_EXCEL_PASSWORD`를 설정했다면 그 값을 우선 사용합니다.
**암호를 소스코드·GitHub·명령어에 기록하지 마세요.**

```text
[OK] 전체 323건 | 신규 323건 | 중복 제외 0건
[DB] .../toss_transactions.db
```

같은 엑셀을 재등록하면 새 거래를 추가하지 않습니다. 조회기간이 겹치는 다른 엑셀도 거래 단위로 중복 여부를 확인합니다.

### DB

- `transactions`: 거래 일시, 적요, 거래 유형, 거래 기관, 상대 계좌번호, 부호가 있는 거래 금액, 거래 후 잔액, 메모 및 중복 판별 키
- `import_runs`: 엑셀 파일별 가져오기 실행 기록 (전체/신규/중복 건수)
- 유니크 제약: `(source_account, fingerprint, occurrence_no)`

중복 판단은 동일 원본 계좌의 **거래일시·적요·유형·기관·상대 계좌번호·금액·거래 후 잔액·메모**를 바탕으로 합니다.
같은 파일 안에 모든 값이 똑같은 행이 여러 건이면 각 발생 횟수를 보존합니다.
원본 엑셀에 은행의 거래 고유번호가 없으므로 실제 거래의 모든 값이 동일한 경우에는 완벽한 식별이 불가능합니다.

잘못된 엑셀·거래 형식은 오류 처리하며 해당 파일의 데이터는 부분 저장하지 않습니다.

### 테스트

```powershell
python -m unittest discover -s tests -v
```

### 보안

은행 거래 원본(`.xlsx`)과 생성된 거래 DB(`.db`)는 Git 추적 대상에서 제외합니다.
**실제 거래내역 파일, 계좌정보, 암호는 공개 저장소에 커밋하지 마세요.**
SQLite DB 자체는 암호화되어 있지 않으므로 별도로 파일 접근 권한을 제한해야 합니다.

## 2단계: 홈택스 현금영수증 제출용 엑셀

> **현금영수증 실제 발급 기능이 아닙니다.** 홈택스 공식 일괄발급 `.xlsx` 파일을 작성합니다. 실제 발급은 홈택스 로그인 후 파일검증 → 일괄발급 → 결과확인이 필요합니다.

### PC 화면 (Windows)

```powershell
python receipt_gui.py
```

1. 먼저 `import_excel.py`로 토스 거래를 SQLite에 저장합니다. 기존 데이터는 삭제하지 않으며 발급 관련 컬럼은 자동으로 추가됩니다.
2. 위 PC 화면에서 입금 거래를 선택하고 **GMT 매출 확인**을 체크합니다. 은행 계좌의 모든 입금이 판매대금인 것은 아니므로 기본값은 **미분류(NULL)** 입니다.
3. 고객이 요청한 **용도구분, 발급수단번호, 공급가액, 부가가치세**를 등록합니다. 거래 ID별 주문정보·메모는 선택입니다. 세액을 임의로 자동 산정하지 않으며 실제 적용 과세기준과 홈택스 양식의 [항목설명]/[부가가치세 계산식]을 확인하세요.
4. 홈택스에서 받은 **공식 엑셀 원본(.xlsx)** 을 선택하고 **제출용 엑셀 만들기**를 클릭합니다. 데이터는 7행부터 작성되며 1개 파일당 최대 1,000건입니다. 양식의 설명·계산식 시트 등 다른 파일 구성은 유지됩니다.
5. 기본 조회 범위는 한국시간 **어제까지**의 입금 중 `GMT 매출 확인 = 예`, `발급 요청 = 예`, `PENDING` 거래입니다. 예를 들어 10월 28일 작업 시 10월 27일 거래를 포함하며 실제 입금일과 현금영수증 발급일은 분리해서 관리합니다.
6. 생성 직후 거래 상태는 `EXPORTED`이며 절대로 `ISSUED`가 아닙니다. 홈택스 발급확인 후에만 아래 `confirm` 명령으로 승인번호와 실제 발급일을 기록합니다.

**현재 임시 가정:** `receipt_requested=1(True)`이 모든 기존/신규 거래의 초기값입니다. 이는 고객의 실제 요청이 확인되었다는 의미가 아니며, 나중에 GMT Hub에서 주문별로 갱신할 수 있도록 독립 컬럼으로 관리합니다. 출금 거래는 내보내기에서 제외됩니다. `receipt_requested=0`인 거래도 현재 내보내기 대상에서 제외합니다.

발급수단번호가 없는 고객 요청 거래는 임의의 공통 번호로 발급하지 않습니다. 특히 자진발급 번호 `010-000-1234`는 고객 발급 요청 거래에 사용하지 못하게 차단했습니다. 공급가액+부가가치세 합계가 입금액과 다르면 내보내기를 중단합니다. 공식 원본 양식은 공개 Git 저장소에 올리지 않고 PC에서 선택합니다.

### CLI (화면 없이도 실행 가능)

```powershell
python receipt_export.py --db toss_transactions.db list

python receipt_export.py --db toss_transactions.db prepare --id 1 --gmt-sale yes --requested yes --purpose 1 --number "010-1234-5678" --supply 27273 --vat 2727 --order-id "ORDER-1"

python receipt_export.py --db toss_transactions.db export --template "홈택스_공식양식.xlsx" --output "현금영수증_제출용.xlsx" --through 2026-10-27

# 홈택스에서 실제 발급 완료와 승인번호를 확인한 경우에만 실행:
python receipt_export.py --db toss_transactions.db confirm --id 1 --approval-no "홈택스승인번호" --issued-on 2026-10-28
```

위 준비 데이터의 번호·세액은 **명령어 예시용 가상정보**이므로 실제 거래에 그대로 적용하면 안 됩니다. 용도구분 코드는 다운로드한 공식 양식의 [항목설명] 시트에서 확인하세요. 출력 파일은 자동 발급이 아니라 업로드용이며, 이미 출력한 거래는 중복방지를 위해 기본 내보내기에서 제외됩니다. 홈택스에서 발급되지 않았음을 확인한 경우에만 `export --retry-exported`를 사용할 수 있습니다.

GMT Hub 자동동기화, 홈택스 사이트 조작 자동화, 이메일 자동수집은 아직 구현하지 않았습니다.

### 홈택스 파일검증 실패 시 재작업

파일 업로드·검증에 실패했다면 **홈택스에서 해당 거래가 실제로 미발급 상태임을 먼저 확인**하세요. PC 화면의 `미발급 거래 재작업` 버튼에서 사유를 남기고 다시 `PENDING`으로 되돌릴 수 있습니다. 이미 `ISSUED`인 거래는 재작업할 수 없습니다.

CLI 예시:

```powershell
python receipt_export.py --db toss_transactions.db reset --id 1 --reason "홈택스 파일검증 실패" --confirmed-not-issued
```

재작업 후 발급정보를 수정하고 다시 엑셀을 생성하세요. 검증 오류를 방치하고 같은 거래를 반복 제출하지 마세요.
